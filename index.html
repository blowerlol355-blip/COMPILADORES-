Glosario Técnico de Compiladores

Términos fundamentales indispensables para comprender la literatura de toolchains y compiladores.

Estructura jerárquica en forma de árbol que representa la estructura sintáctica abstracta del código fuente. Cada nodo del árbol denota una construcción que ocurre en el código fuente, omitiendo detalles puramente sintácticos como puntos y comas o paréntesis redundantes.

Propiedad fundamental de representaciones intermedias modernas donde a cada variable se le asigna un valor exactamente una vez. Cuando convergen diferentes ramas de ejecución, se utilizan funciones especiales llamadas Φ (Phi nodes) para determinar cuál versión de la variable utilizar. Simplifica drásticamente optimizaciones como la propagación de constantes y la eliminación de código muerto.

AOT: El código se compila completamente a binario nativo antes de ser distribuido o ejecutado (ej. C, C++, Rust, Go, Zig). Máxima velocidad inicial y cero overhead de compilación en tiempo de ejecución.

JIT: El código se compila durante su ejecución en la máquina del usuario (ej. V8 para JavaScript, JVM, PyPy). Permite optimizaciones especulativas basadas en el comportamiento real en tiempo de ejecución, pero añade latencia de arranque (warmup).

Técnica donde el compilador pospone la optimización final hasta la fase de enlazado, preservando el código intermedio (ej. LLVM IR o GIMPLE) dentro de los archivos objeto. Esto permite hacer inlining de funciones que cruzan diferentes archivos fuente (unidades de traducción) y eliminar bibliotecas no utilizadas de forma global.

Componente del compilador rustc que analiza estáticamente el grafo de flujo de control (MIR) para garantizar que las referencias a memoria nunca sobrevivan a los datos a los que apuntan, y que no existan accesos concurrentes mutables a la misma porción de memoria, eliminando condiciones de carrera (data races).

Representación intermedia gráfica que combina el grafo de flujo de control (CFG) con el grafo de dependencia de datos en una sola estructura sin orden secuencial estricto. Esto otorga al compilador máxima flexibilidad para reordenar y optimizar instrucciones sin las restricciones impuestas por la secuencialidad original del código.
